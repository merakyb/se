## 1. 서론

### 1.1 문서 목적 및 범위

본 프로젝트 계획서는 **주차를 왕처럼 편하게, King Parking** 에 대한 전반적인 내용을 정리하여 프로젝트를 진행하는 데 있어 각 세부 사항의 지표로 삼는 것을 목적으로 한다.

본 문서는 다음과 같은 범위의 세부 사항의 지표로 삼는 것을 목적으로 한다.

본 문서는 다음과 같은 범위의 지표로 적용할 수 있다.
* 1. 프로젝트 개요 ( 프로젝트 정의,주요 기능 정리 )
* 2. 개발 계획 및 환경 ( 개발 절차 모형, 내용 및 일정, 소프트웨어/하드웨어 환경 )
* 3. 팀 구성 ( 팀 구조/역할 및 책임 )
* 4. 품질관리 ( 팀 미팅, 변경 사항 및 산출물 관리 )
* 5. 산출물 ( 산출물 정의, 작성일 및 담당자 )

### 1.2 프로젝트 개요

#### 1.2.1 프로젝트 정의

자주 사용하지 않는 사적 공간이나 애매한 크기의 사적 공간들을 주차 공간으로 활용할 수 있도록 주차 공간을 등록 및 관리할 수 있는 어플리케이션을 제작한다.

#### 1.2.2 주요 기능 설명

| ID | 설명 |
|------|-----------------------|
| F01 | 주차 공간 등록 및 관리 |
| F02 | 주차 공간 예약 |
| F03 | 주차 요금 결제 |
| F04 | 실시간 주차 현황 확인 |
| F05 | 예약 시간 알림, 주차 종료 알림 | 

### 1.3 프로젝트 목표

자주 사용하지 않는 사적 공간이나 애매한 크기의 사적 공간들을 주차 공간으로 활용할 수 있도록 주차 공간을 등록 및 관리할 수 있는 어플리케이션을 제작한다.
언제든지 사적 공간을 활용하고 싶은 사용자는 주차 공간을 등록하고 주차 공간을 찾고 있는 사용자는 실시간으로 근처 주차 공간을 확인할 수 있는 서비스를 제공한다.


## 2. 개발 계획

### 2.1 개발 절차 모형

본 프로젝트는 요구사항 변경 가능성이 존재하고, 기능을 점진적으로 개선하기 위해 Agile 기반의 Scrum 개발 방식을 적용한다.

다만 본 프로젝트는 1인 개발 환경이므로, 팀 단위 회의 대신 개발자가 직접 개발 계획을 수립하고 수행 결과를 점검하는 방식으로 Scrum 프로세스를 적용한다.

Sprint 단위로 기능을 반복적으로 개발하고, 각 단계마다 결과를 검토 및 개선하는 반복적(Iterative)이고 점진적(Incremental) 개발 방식을 따른다.

또한 객체지향 설계 방법을 적용하여 모듈화된 구조를 구성하고 유지보수성과 확장성을 확보한다.

## 3. 팀 구성

### 3.1 팀 구조

본 프로젝트는 1인 개발 프로젝트로 수행되며, 단일 개발자가 전체 개발 과정을 담당한다.

다만 효율적인 프로젝트 수행과 체계적인 관리를 위해 프로젝트 관리, 설계, 구현, 테스트의 역할을 논리적으로 분리하여 수행한다.

따라서 본 프로젝트는 중앙집중형 구조를 기반으로 하며, 개발자가 모든 의사결정과 개발 활동을 수행하는 구조를 가진다.

본 프로젝트는 1인 개발 환경이지만 역할을 분리하여 수행함으로써 관리 효율성과 품질을 확보한다.

## 4. 품질 관리

#### (1인 개발이므로 팀 미팅 계획은 개발 점검 계획으로 바꾸어서 작성하였습니다.)

### 4.1 개발 점검 계획

본 프로젝트는 1인 개발 프로젝트이므로 별도의 팀 미팅은 진행하지 않는다.
대신 개발자는 정기적으로 개발 진행 상황을 점검하고, 계획 대비 진행률과 문제 발생 여부를 확인한다.

* 점검 시간: 매주 1회
* 점검 내용: 개발 진행 상황, 기능 구현 여부, 오류 발생 여부, 다음 작업 계획
* 점검 방법: 개발자가 직접 진행 상황을 기록하고 필요한 경우 개발 계획을 수정한다.

---

### 4.2 변경사항 관리 방법

* 기능 변경이 필요한 경우, 변경 사유와 변경 내용을 문서에 기록한다.
* 변경 전후의 차이를 확인할 수 있도록 Git 커밋 이력을 남긴다.
* 요구사항 변경이 발생하면 기존 일정과 기능 구현 범위에 미치는 영향을 먼저 검토한다.
* 변경 사항이 프로젝트 목표에 적합하다고 판단될 경우 개발 계획에 반영한다.

---

### 4.3 산출물 관리 방법

#### (1) 산출물 명명 방법

* 문서: `[문서명]_YYMMDD_Doc-버전`

  * 예: `KingParking_프로젝트관리계획서_260424_Doc-001`
* 소프트웨어 : 기능 또는 모듈명을 기준으로 명명한다.

  * 예: `UserService`, `ParkingReservation`, `PaymentModule`
* 기타 파일: 파일의 목적이 드러나도록 작성한다.

  * 예: `예약기능_테스트결과_260424`

#### (2) 산출물 버전 관리 방법

* 소프트웨어는 Git을 이용하여 버전 관리한다.
* 기능 추가나 수정이 발생할 때마다 커밋 메시지를 작성하여 변경 이력을 남긴다.
* 문서는 수정 시 버전 번호를 갱신하고, 변경 내용을 기록한다.

#### (3) 산출물 저장 방법

* 소프트웨어: GitHub 저장소에 저장한다.
* 문서 파일: 로컬 저장소 및 클라우드 저장소에 함께 보관한다.
* 테스트 결과 및 참고 자료: 프로젝트 폴더에 분류하여 저장한다.
